## C. 十条硬结论

1. **别背答案。** dev 和 Test 是两本不同的剧本，官方明说"防止选手过拟合"。背 dev 不涨分，还可能判 0。
2. **真正的分水岭是门禁不是分数。** 32% 的队被直接清零，最高频死因是 mode 写错和把隐藏事件后果写成查表。
3. **机制层 > 内容层。** 引擎怎么算、什么时候判、cap 怎么封——这些跨剧本通用；事件名、选项原文、精确增减值——这些一换池就废。
4. **闭卷下先做离线取证。** 一局几十块，历史 jsonl 是免费的金矿：门槛、失败条件、调用画像全能从里面反推。
5. **60,000 字符是硬墙。** 超了就尾部硬切、无标记、停在句子中间。策略包必须分层：常驻层（每步都生效）vs 按需层（命中才读）。
6. **自动扫描会漏。** 逐字匹配对"截短 2–5 字"的改写完全无感；必须再加一层 8-gram 模糊层 + 人工形态 grep（事件名/链名/run id/选项引号+数字）。
7. **硬表一定要挂保险丝。** 包里所有 cap/门槛都来自 dev 直读；Test 若换了剧本级配置，硬表整体失效而 Agent 永远发现不了。SAT 饱和自检是局内唯一能发现它的机制。
8. **L1 不能熬。** v63 实测 14.73 分、24 月被炒——L1 的 N cap 只有 3，锁死 perf，半年两次 perf<4 直接出局。
9. **n=1 不许定论。** 跑一局就宣布"提了 4 分"是本次比赛最贵的坏习惯。要归因，先跑同版本相邻局对照。
10. **文本自洽 ≠ 事实正确。** 我们有一版 SKILL 里 9 处写着"回血 2E"，引擎原文里根本没有这个数；只有回原文才查得出来。

## D. 三条跑通的检验标准

一个策略包"可以提交"的最低门槛（我们的实测输出形态）：

```
[ OK ] A1 manifest.json 存在且可解析
[ OK ] A2 mode 合法（"agent"）
[ OK ] A3 team / name / instruction 非空
[ OK ] A4 包结构 skills/<id>/SKILL.md 齐全
[ OK ] A5 包内不含模型文件
[ OK ] A6 体积 ≤ 2MB
[ OK ] A7 每个 SKILL.md 有合法 YAML frontmatter
[ OK ] B1 无「事件+选项+增减值」查表结构
[ OK ] B2 无「读取隐藏状态」指令
[ OK ] B3 无「解码规则数据」措辞
[ OK ] C1 常驻层 ≤ 58,590 字符
[ OK ] C2 行尾统一 LF
结论：FAIL=0  WARN=0
官方 validate：3 / 3 PASS
```
