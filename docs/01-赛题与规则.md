# 01 · 赛题与规则

> 这一篇回答："这个比赛到底要干什么、交什么东西、什么情况会被判 0 分。"

## 1.1 赛题长什么样

**CCF BDCI 2026 · Agent 职场长程生存与晋升挑战**（出题方 openJiuwen）。

一个 Agent 被扔进一段 48 个月的职场人生：

- 每**季度**发 3 点 Energy（**不累积，季度末清零**），要分配到若干"体力恢复/技能/人脉"类动作上；
- 每**季**有 1 个主行动；
- 每回合可能撞上**突发事件**，从几个选项里挑一个；
- 屏幕上有 **9 个可见状态字段**（Health / Dignity / Skill / Network / Output / Wealth / Level / Energy / CurrentLevelDuration），还有**读不到的**隐藏状态（hidden_risk 等）；
- 撞上失败条件（连续半年绩效 < 4、Health/Dignity 见底、风险爆表…）就**出局**；
- 凑够门槛在指定月份**晋升**，一路 L1 → L7。

评测：云端统一评测 **70%** + 专家评审 **30%**（**初赛只有云端**）。
赛期：每日 1 次提交，**最终分取历史最高**；单份 ≤ 2MB。

## 1.2 提交格式（很关键，写错直接 0）

一个最小的合法提交包长这样：

```
solution/
├── manifest.json              # 必须有：team / mode / name / instruction
│   { "mode": "agent", ... }   # mode 填错 = 最高频的判 0 原因
└── skills/
    ├── cor-career/SKILL.md    # 至少一个 skills/*/SKILL.md
    └── cor-window/SKILL.md
```

官方 validate 只查**三项**（`career_sim_runner/validate.py:validate_submission`）：

| check | 校验 |
|---|---|
| `submission-layout` | `manifest.json` 存在 ＋ 至少一个 `skills/*/SKILL.md` |
| `manifest-fields` | `team`、`mode` 字段合法 |
| `skill-frontmatter` | 每个 `SKILL.md` 的 YAML frontmatter 合法 |

> ⚠️ **validate 3/3 不等于能交。** 它只证明"格式合法"——**不验证策略、不验证分数、不验证有没有过拟合**。真正要命的判 0 不在这三项里，见下节。

## 1.3 官方门禁：判 0 的 N 种死法

这是全篇最该记住的一节。来源：官方四天公示（`_official_scores/`）+ 我们 2026-10-02 现抓的官方规则页。

| 门禁失败原因（官方原文归类） | 出现天数 | 判 0 性质 |
|---|---|---|
| **模式错误，使用 `agent.fast` / `agent.plan` 等不支持的模式** | 四天均有，**最高频** | 清零 |
| **把模拟器隐藏的事件后果预先写成查表** | 9/23、9/29 | 清零 |
| 在 skill / manifest 中写死了情节答案 | 9/23、9/24、9/27、9/29 | 清零 |
| 违规从模拟器规则数据解码 | 9/23、9/29 | 清零 |
| 尝试读取隐藏状态 | 9/23、9/29 | 清零 |
| 缺 `manifest.json` / 包结构错误 | 9/23、9/24、9/27 | 清零 |
| 提交包含模型 | 9/24 | 清零 |

**四天全赛道分布**（`官方成绩公示-20261003.md`）：

| 提交日 | 提交队数 | 有效分记录 | 最高分 | 最低有效分 | **0 分队数** |
|---|---:|---:|---:|---:|---:|
| 9/23 | 63 | 50 | **63.31** | 14.56 | 13 |
| 9/24 | 42 | 32 | 62.99 | 14.88 | 10 |
| 9/27 | 62 | 55 | 62.43 | 31.10 | 7 |
| 9/29 | 67 | 61 | 62.62 | 15.52 | 6 |

⇒ 最高分区间 **62.43–63.31 极稳**（不是随机波动）⇒ **体系上限 ≈ 63**。
⇒ **约 32% 的队伍被清零**——这比"能不能上 60 分"重要一个数量级。

还有一条反直觉的：**判 0 ≠ 取消资格**。举例队伍 `362157`：9/23 = 14.56 → 9/24 = 0（违规写死答案）→ 9/27 = 0 → 9/29 = 15.52。

## 1.4 官方对"过拟合"的原话

2026-10-02 20:15 现抓 `competitions/1165` 规则页，逐字：

> 「请勿尝试解码或绕过评测规则。包括**针对评测机制写死答案、硬编码预设输出**，或以其他方式使 Agent 直接"抄答案"等，均属于违规行为。」
> 「设置 **Dev 剧本**（公开）用于验证脚本可运行性，**Test 剧本**（保密）用于正式打分，**防止选手过拟合**」

这两句话把整个赛道的策略空间划死了：

- dev 是给你**验证脚本能不能跑**的，**不是给你刷分的**；
- 任何"从 dev 数据反推 Test 答案"的动作，既是浪费，也是风险；
- 唯一跨池可迁移的东西 = **引擎机制层 + 通用规划层**。

## 1.6 一条容易被忽略的成本：信封截断

提交包不是"写完就完了"——它会**被塞进每一次工具调用的上下文里**，而上下文有硬上限 60,000 字符（怎么发现的见 [06 §2](06-反过拟合与泛化.md#22-60000-字符信封截断)）。

| 版本 | SKILL 字符 | 被切 |
|---|---:|---:|
| v55b（9/25） | 100,348 | **41.1%（41,258 字符）** |
| v60r / qe7（9/29） | 108,215 | **45.4%（只送达 55%）** |
| qe21（10/02） | 63,888 | 4,799 字符 / 76 行（含**整节常驻红线** + **整节附录索引**） |
| qe22 / qe23 / qe24 | 58,507 / 58,344 / 58,237 | ✅ 窗内 |

qe21 被切掉的 10 个小节里，有两个是"每步生效"的关键：**`## 常驻红线`（8 条逐字诱饵 + 通用规则）** 和 **`## 附录索引`（9 行映射表 + 加载铁律 0–5）**。
⇒ 出现了一个诡异状态：**文件开头的阅读路由表在送达区，明写"红线看文末常驻红线"，而那一节一次都没进过上下文。**
⇒ 结论：**"外置"是一次性节食，不是结构性修复**。v60r 越写越长，外置只顶住三版，qe11 起又逐版越线。
