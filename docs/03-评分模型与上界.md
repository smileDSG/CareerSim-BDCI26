## 3.3 上界为什么是 79.03

把每个维度推到它的**可达上限**（不是理论上限，是 48 个月内引擎实际能发出来的上限）：

| 约束 | 损失 |
|---|---|
| L7 不可达（S 峰值 163 < 门槛 170） | 拿不到最后一档 |
| **L5 段 N 封顶 54 < 60** | **必丢 1.0** |
| risk_control 只能靠压 hidden_risk（不可见，只能保守估计） | 带 [0, +x] 区间 |

⇒ **79.03**。历史最好局 **78.96**，差 0.07。

** our 读法**：78.96  ↔ 79.03 只差 0.07，说明**在本地 dev 侧我们已经摸到天花板了**——继续在"选哪个选项"上抠 ±0.5 分，边际收益接近零，风险却是真实的（过拟合判 0）。这直接决定了后期的重心：**从抠分转向保命 + 保泛化**。

## 3.4 一个反直觉的发现：真正的杠杆是 wealth，不是 S

8/29 那次全文件扫描 + 分来源分解，得出：

- 职级权重最重（0.30），但**它是离散台阶**，一步错重启（L1 熬过 M6 就是另一条时间线）；
- skill 权重 0.15 但归一化区间是 [0,120]，**边际递减很重**；
- **wealth 没有动作来源**——体力/主行动都不产 W。W 只来自：月薪（× level）、半年奖（× perf 档）、事件免费 W+、选项里带 W 的分支。
- ⇒ **W 是完全被动的、且完全可预测的**（月薪 = level × 常数，教科书式确定）。

这条把策略重心推了一大步：**与其在 S 上抢那 1 分，不如把 W 的每一分都拿到**——它是确定性的，不依赖事件抽样。

也顺手证伪了一条：*"把 N 分出去就能换到 S 分"* —— 数据不支持（N 是 S 动作的免费副产品且 score-neutral），8/28 那版据此改的 SKILL 全部作废，一天白跑。

## 3.5 门禁式的最低可接受分

这套赛制里，"多少分算及格"不是相对的，是绝对的——因为 32% 的人直接 0：

| 结果 | 含义 |
|---|---|
| 0 | 过门禁失败，什么策略都不谈 |
| < 30 | E |
| 30–50 | D/C |
| 50–62 | 有分但不上榜首区 |
| 62–63 | 天际区（四天极稳） |

⇒ **把"别判 0"排在所有提分之前**，是这次最划算的一个决策。

## 3.6 口径提醒

- **本地 `quantitative_score` ≠ 官方最终分**。官方 = 云端统一评测 70% + 专家评审 30%。
- 本仓库里所有"官方分"是云端公示的 quantitative 口径。
- 离线兜底算分（[07 §4](07-工程与跑局复现.md#44-离线算分体系)）给的是**下界**（缺尾调用），所以按上带报。
