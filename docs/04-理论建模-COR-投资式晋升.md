# 04 · 理论建模：COR 与"投资式晋升"

> 这篇讲我们**怎么用管理学/经济学的现成理论搭决策层**，以及为什么最后**一个模型都没训**。

## 4.0 先说结局

五周之后，**COR（资源保存理论）是唯一留在最终系统里的模型**，而且它退化了——从"效用优化器"退化成"**否决壳**"（veto shell）：不做决策，只负责一票否决。

这不是失败。**理论在这里的价值是"帮你想清楚变量之间的关系"，而不是"给你一个能跑的数"。**

## 4.2 COR 资源保存理论（Hobfoll 1989）

**定义**：资源 = 被个体看重、且能用来获取或保护其他资源的事物。四类：

- **Objects** 客观物品
- **Conditions** 条件（职级、身份）
- **Personal** 个人特质（技能）
- **Energies** 能量（体力、精力、财富）

**核心是商队隐喻（caravan）**：资源像商队一起流动，丢一个会带丢一批。

**实际采用的三大原则**：
1. **损失比同等增益更显著**（损失厌恶）
2. **资源必须靠投资才能积累**（所以"省着用"是错的）
3. **损失螺旋**（掉了一个，下一个更掉）

**价值函数**（含损失厌恶 λ≈3）：

```
V(R) = Σ_i w_i · ( λ·g(−Δr_i)   若 Δr_i < 0
                   g(Δr_i)       若 Δr_i ≥ 0 )      λ_loss ≈ 3·λ_gain
```

**状态演化**：`R_{t+1} = R_t + ΔR(a_t) + ξ_t`

**硬约束（资源地板）**：`R_k ≥ ρ_k`（ρ_H = ρ_D = ρ_N = 2, W > 0, Risk < 5）

**晋升阈值**：`R_k ≥ Θ_k`

### 为什么最后变成"否决壳"

COR 原教旨做法是把 V(R) 丢进求解器做期望最大化。试过了：

- 引擎里的事件收益是**隐藏的**（dev 数据可用，Test 不可用），闭卷下 V(R) 里的 `ΔR(a_t)` 估不准；
- 估不准就做不出"最优"，只会做出**自信的错误答案**（这条是后面最贵的一课，见 [08](08-关键战役复盘.md)）；
- 但 COR 里**最稳的那部分**——"有地板"、"别把资源耗光"——完全不依赖收益估计。

⇒ **砍掉估计，保留否决**：
```
每季决策前先查 R_k < ρ_k + margin，命中 ⇒ 一票否决"冲晋升"，强制保命动作。
```
代码就是 `cor_veto_shell.py`，几十行。它救过局：100 局模拟显示**纯成长和纯保命两种极端策略存活率都是 0%**，只有 COR 优先级能活。

## 4.3 投资式晋升策略（PRS）

思路来自"投资择时"：晋升不是越早越好，**是等资源齐了再冲**。

**就绪分 PRS**：

```
PRS = w1·(H/10) + w2·(D/10) + w3·Cs + w4·(1−R) + w5·Ld
      Cs = 资本达标率，R = 活跃风险，Ld = 停留时长进度
```

例：H=6→0.6、D=7→0.7、Cs=0.8、R 低→0.9、Ld=0.7 ⇒ PRS ≈ 4.1/10

**动态阈值（择时器）**：门槛随月份线性放宽，因为后期窗口机会变少：

```
threshold(m) = T_high − (T_high − T_low)/48 · m
（例：T_high=4.5、T_low=3.5 ⇒ 第 12 月 4.25，第 40 月 ≈3.67）
```

**决策算法**：

```
非窗口期        → ACCUMULATE（攒）
if H≤2 or D≤2  → RECOVER      （哨兵一票否决）
elif R 高       → DEFUSE       （排雷）
elif PRS ≥ threshold 且 R 低 → PROMOTE
else           → ACCUMULATE
```

七项改善：全期路线图、动态阈值、DelayCost、高效等法、主动排雷、replay 拟合权重、风险哨兵一票否决。

## 4.4 另外四个模型（及它们为什么没进运行时）

| 模型 | 公式 | 进运行时了吗 |
|---|---|---|
| **AMO 绩效模型** | `P = A × M × O`（乘积，任一项为 0 则整体归零） | 否（留作解释） |
| **Vroom 期望 + Adams 公平** | `M = (E·I·V) · g(Ineq)`，`g = clamp(1+β·Ineq, g_min, 1)`，β≈0.5 | 否 |
| **Simon 有限理性（满意决策）** | `b_{t+1}(h) ∝ P(o_t\|h,a_t,s_t)·b_t(h)`；选**第一个**满足 `f(ŝ') ≥ A 且 R_k ≥ ρ_k` 的 action | 部分（抱负 A 进 SAR） |
| **贝叶斯更新隐藏阈值** | 对隐藏的 `hidden_risk` 维护信念分布，随观测更新 | 否（hidden_risk 根本读不到） |

> 关于 Vroom：数字例 E0.9×I0.7×V0.9 = 0.567，I 崩到 0.3 ⇒ 0.243；自己 Q=1.89 vs 同 Level 同事 Q=2.20 ⇒ Ineq = −0.31 ⇒ M = 0.479。这套当时写得很完整，但**它依赖"同事基准值"，这玩意儿在闭卷里拿不到**。

## 4.5 最终形态：NRC-Agent 五层嵌套

```
max_π  E[ Σ_t γ^t · Σ_i w_i(m) · r_i(s_t, a_t) ]
s.t.   (a) R_k(s_t) ≥ ρ_k   ∀k        (b) CVaR_α[L] ≤ κ
```

从外到内五层：

1. **元层**：有限理性（信念 b + 抱负 A）—— 决定"满意度标准"
2. **动机层**：E·I·V·g(Ineq) —— 决定"这件事值不值得拼"
3. **绩效层**：A × M × O —— 决定"拼了有没有产出"
4. **资源层**：COR 硬底线（**否决壳**）—— 决定"能不能赌"
5. **外层**：职业生涯时间轴权重 w_i(m) —— 决定"什么时候该看重什么"

**文档里的原话**：「写码必须保留这五层结构，否则会塌成扁平大杂烩。」

## 4.6 没做的事（同样重要）

- **没有微调、没有 RL、没有本地训练。** 全程 = LLM 规划 + Python 硬校验 + 提示词。
- **明确否掉了 PPO**，理由：可解释、可复现、比赛要的是"稳定 84 档"不是"方差更小的 90 档"。
- **没有多 Agent 协作**，单 Agent 单流程。
- **指导老师建议的"Python 符号决策引擎"，我们只采纳了方向、没做完整重构**，只做提示词级改动 + 三 Skill 拆分——因为完整重构有回归到 79.38 的风险，收益不确定。

## 4.7 这条路的收益

- **7 月那套理论最大的产出不是代码，是问题定义**：把"怎么打这个游戏"翻译成"资源地板 / 晋升阈值 / 时机成本"三个变量，后面所有逆向工作都是给这三个变量填数。
- **第二个产出是"否决壳"这个形态**：它后来演成了整包里最硬的一条规则（`cor_veto_shell.py` 的语义在 SKILL.md 里变成"禁止以维换维"/"贴线维恒记 −1"）。
- **第三个产出是被证伪的部分**：8/28 那天推翻的「N 换 S」、8/29 推翻的「N 溢出是浪费」、8/31 推翻的「L1 滑档」——**每一次证伪都阻止了一次真实的退步**。
