## 5.2 三条最重要的：v62 / v63 / v67

### v62 —— 破平兜底（现在是每包的标配）

**问题**：三档平手走完还是平，Agent 就开始乱选、来回摇摆。
**修法**：关键词表给 action 文本打分 → 再平按字典序。**明确禁止"按位置序"选**（那就是把顺序当成信号，是过拟合）。

### v63 —— 🔴 崩盘 14.73（详见 [08 §1](08-关键战役复盘.md#1-战役-a-v63-崩盘1473--e-级--24-月出局)）

一句话：**把"已达门槛、未满 cap"那一档的计价从"门票价"（+3 ÷ 缺口）砍成"常规单价"（S 0.125/点，约降 24 倍）** ⇒ L1/L2 边际激励归零 ⇒ 只守不进 ⇒ L1 N cap=3 锁死 perf ⇒ 半年两次 perf<4 ⇒ 炒鱿鱼。

### v67 —— 判定帧硬格式 + SAT 饱和自检

**判定帧硬格式**：把"我现在离晋升还差多少"钉在每帧尾部（`CAP-SNAP` 行），剩月 ≤1 时逐维补写余量，**任一余量 <0 就禁选**。
改造 `manifest.instruction` 10,580 → 10,678 字符。

**SAT（saturation）饱和自检** = 保险丝，见 [06 §4](06-反过拟合与泛化.md#44-sat-保险丝)。

## 5.3 废弃档为什么不可信（两条铁律）

### v64 = 49.14

仍出在"判定帧余量"这一点上（M18 缺 N 1 点 / M30 缺 O 2 点 / M18 缺 O 1 点）。
附带一个引擎知识：`d > 缓冲(X)` 里的「连」**是真的连续**，中间一次「佳」即重置计数（我们此前误以为是非连续累计）。

### v65 = 54.79

**闸门全程触发 0 次**（`待补` 计数 = 0）⇒ 相对 v64 的 **+5.65 不能归因于闸门**，本局对"闸门是否有效"**零信息量**。
真正的病：`ref-2.2c-errata.md` §2.2c ⑥ 是无条件 `d > 缓冲 ⇒ 禁选`，与 v65「剩月够就能补回」**互斥**；**M17 Agent 自己写着"贴线、已跌破 M18 门槛"仍然选掉 O 项**（所有候选 blanket −1，无从分辨）⇒ **15.3 分的差距追溯到 M18 那 1 点 O**。

> **这就是"规则有但没执行"的典型**，也是 v70 里 §2.3c 硬边界存在的理由。

## 5.4 最后为什么选 r9

不是因为它分最高（r5 是 78.29，r9 没跑过完整局），而是因为它是**唯一一个全部绿灯的发布态**：

```
过拟合  模糊层 0 行 ＋ 精确层 0.0% / 0.0% / 0.0%
硬门禁  FAIL=0  WARN=0
官方    validate 3/3 PASS
打包    zip 287,406 B / 31 条目 / ALL MATCH
窗口    常驻层 58,535 字符（安全线 58,590，余 55）
行尾    全 LF
```

r5 与 r8/r9 差 17 分（**n=1 vs n=1，不许定论**）。三个归因候选都还悬着：

1. dev 清理的代价（`§2.3` 那张「关键词 → 平均 S 系数」表有 10 个词，是本地选高 S 选项的主力依据）；
2. 单局方差；
3. 环境差异。

要拆开，得再跑**同版本相邻局各 2 局**——我们没跑到（赛期截止），**如实写在这**。

## 5.5 版本管理上的两条纪律

1. **一个 zip 一个 hash**：包目录不许留备份/临时文件，改完必跑 `zip ↔ 磁盘 31/31 md5 一致`；
2. **README 自述数字必须回填**：「任何改动 SKILL.md 的版本，打包前必须重跑 README 自述数字 vs 实测比对」——**同一个坑踩过两次**（qe22、qe24 各一次，README 目录行还写旧值，包就被重建一次）。
