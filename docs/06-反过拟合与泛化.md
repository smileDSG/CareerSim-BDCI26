# 06 · 反过拟合与泛化 ★

> 这是**整个复盘里最值得看的一篇**。
> dev 和 Test 是两本不同的剧本，官方原话是「防止选手过拟合」——这意味着**背 dev 不但不涨分，还会被判 0**。
> 那么问题变成：**在完全闭卷的前提下，怎么写一份"看得见"的策略包？**

## 6.1 先把过拟合定义清楚

我们的操作定义（写在 `_overfit_audit.py` 文件头）：

> 把 dev 真值表（附录 G：**171 个事件标题 + 971 条选项原文**）在**交付包全部文本文件**里做**逐字**匹配。命中的比例 = 交付包里「可被 Test 池直接判废」的内容占比（**下界**）。

官方侧的定义（`competitions/1165` 规则页，逐字）：

> 「请勿尝试解码或绕过评测规则。包括**针对评测机制写死答案、硬编码预设输出**，或以其他方式使 Agent 直接"抄答案"等，均属于违规行为。」
> 「设置 Dev 剧本（公开）用于验证脚本可运行性，**Test 剧本（保密）**用于正式打分，**防止选手过拟合**」

## 6.2 两层扫描：精确层不够

| 层 | 脚本 | 方法 |
|---|---|---|
| **精确层** | `_overfit_audit.py` | dev 选项原文 **≥8 字逐字** `in` 包内文本 |
| **模糊层（按文件）** | `_overfit_fuzzy.py` | dev 语料切 **8-gram** 与包内取交集，贪心扩展出**最长连续命中片段**并回显出处 |
| **模糊层（逐行）** | `_overfit_scan_lines.py` | 同上，但逐行输出 + 回显 dev 原文出处 |
| **人工形态层**（自动层之后） | 手工 grep | grep「事件链 / run id / 选项引号 + 数字」 |

### 为什么必须有模糊层：三个真实例子

旧脚本只做逐字匹配。包里条目**被截短 2–5 字**后，整条就躲过去了：

| dev 原文 | 包里实际写的 |
|---|---|
| 向 Leader 争取以兼职形式参与**新项目** | 向 Leader 争取以兼职形式参与（还带着一模一样的 `O−1 N+1 S+1 H−1 R+1`） |
| **婉拒换班，**请 Leader 按规则统一协调 | 婉拒＋请 Leader 按规则统一协调（还带着 `ΔO−1 ΔN−2`） |
| **继续**随波逐流、走一步看一步 | 随波逐流、走一步看一步 |

**"少两个字"在逐字匹配眼里是两条不同的规则，在 Test 池眼里是同一条。**

## 6.3 60,000 字符信封截断

### 这个上限哪来的？（诚实说明）

**它不是从引擎源码读出来的。** 本机 `career_emulator` 和仓库里都 grep 不到 `60000` / `truncat` / `MAX_*_LEN` 常量（jiuwenswarm 框架源码本机没装）。

它是**从 136 局历史事件流反推**的，三条证据：

| 证据 | 内容 |
|---|---|
| **E1** | 完整信封最长 = **58,905 字符**；被切信封最短 = **60,000**，且被切后长度**恒为 60,000**、没有一条超过 ⇒ 阈值落在 (58,905, 60,000] |
| **E2** | 跨 4 种工具同一个整数：`skill_tool` 32 次调用/17 次恰为 60,000；`read_file` 598 次/37 次；`grep` 627 次/1 次 ⇒ 统一结果预算，不是单工具个性 |
| **E3** | 形态 = **尾部硬切、无标记、停在句子中间** |

**口径换算**：60,000（信封）× −≈910（外壳）⇒ 正文可用 **59,090**；安全线取 **58,590**。

**没查清的**（如实写）：60000 是否可配置、上限在送达还是落盘路径生效、有没有受控实验 —— 都没有。

### 常驻层 vs 按需层

`SKILL.md` 自述三层：**〔常驻〕每步都生效、不必查也不能忘 ｜ 〔触发〕命中才读 ｜ 〔按需〕用一次读一次**。

| 层 | 内容 | 位置 |
|---|---|---|
| **常驻层** | 两份 `SKILL.md` 正文（cor-career 判据层 + cor-window 调度层），每次整体送达 | 58,535 字符 |
| 〔按需〕 | `references/` 下 19 个文件 | 命中才读，**一次只读一张** |

**加载协议**：附录索引给「§2.2 阶梯判定 → 读哪个 references 文件」9 行映射表；铁律：**按起始行号 `read_file(offset=行号-1, limit=20)` 一次取整节**，禁多词宽扫；**禁止开局把六份全读一遍**（那等于回到 1007 行，照样被切）。

### 实测代价

| 版本 | SKILL 字符 | 被切 |
|---|---:|---|
| v55b | 100,348 | **41.1%（41,258 字符）** |
| v60r / qe7 | 108,215 | **45.4%（只送达 55%）** ❌ |
| qe8/qe9/qe10 | 57,080 / 57,080 / 59,045 | ✅ 首次落回窗内（**只顶住三版**） |
| qe11→qe20 | 59,915 → 63,153 | 826 → 4,064 **逐版加深** |
| qe21（10/02） | 63,888 / 823 行 | 4,799 字符 / 76 行 |
| qe22/qe23/qe24 | 58,507 / 58,344 / 58,237 | ✅ 窗内 |

qe21 被切掉的 10 个小节里有两个是"每步生效"的：**`## 常驻红线`（整节）** 和 **`## 附录索引`（整节）**。
⇒ 诡异状态：**文件开头的阅读路由表在送达区，明写"红线看文末常驻红线"，而那一节一次都没进过上下文。**
⇒ **危害是机制性的**：① 指针到了、目标没到；② 丢的是兜底，而兜底只在坏局用 ⇒ 双重失效。

**反证（也是我们的自我约束）**：本机 9/25 那两局（78.78 / 78.04）用的就是同一份被切 41% 的文档 ⇒ **没有任何一局被证明因截断而失分**；上限造成多少分损失**不可测**。

> **结论**：外置（把内容挪去按需层）是一次性节食，**不是结构性修复**。真正的修复是**把常驻层压到 58K 以内**，且每版都要重算窗余。

## 6.4 SAT 保险丝

**SAT = saturation 饱和自检**，写在 `SKILL.md` 常驻层 + `manifest.instruction` 同步 1 句：

> 若某维**未达**表内 cap 却执行明确 `+X`、`observe` 后**完全没变**，或现值**超过**表内 cap ⇒ 判定**硬表在本局失效**，该维停手线 `eff` 按本局实测重算；**晋升后 SAT 重置**。

**为什么必须有**：包里所有 cap / 门槛 / 饱和线**全部来自 dev 引擎直读**。若 Test 池这些参数是**剧本级配置**而非引擎常量 ⇒ 硬表整体失效，而 **Agent 永远发现不了**。SAT 是**局内唯一能发现它的机制**。

配套：硬表族共 13 处，`_v67_audit.py` 实抓「只有 SAT 自身挂了标记」⇒ 给最硬的引用点（表头、L411、L538）挂**具名例外**，其余 8 处引用点自动继承。

## 6.5 `seen` 账本：唯一保留的"经验"

不是记忆事件名，是**记 (事件, 选项) → 本局实测符号**：

- 跨月复现：符号一致率 **100%（846 对）**；
- 覆盖 14.4% → 18.9%，**准确率 99.7% 不变**；
- **零 dev 内容**（只记自己本局实测过的）、**不拟合常数**、**池无关**。

⇒ 这是"从历史里学"和"背答案"的分界线：**账本记的是"我试过，它是这个符号"，不是"这个事件的标准答案是 X"。**

## 6.6 三层自检链（提交前必跑）

```bash
$V _overfit_audit.py      <pkg>   # 精确层：指标 1/2/3 应全 0.0%
$V _overfit_fuzzy.py      <pkg>   # 模糊层（按文件汇总 + 最长连续命中）
$V _overfit_scan_lines.py <pkg>   # 模糊层（逐行 + 回显 dev 出处）
$V _preflight_hardgate.py <pkg>   # 硬门禁 → 输出 __hardgate_<ts>.txt，看 FAIL/WARN
$V _v67_audit.py          <pkg>   # 死锁/优先级链/硬表例外/冗余/README 重复
$V _nofit_verify.py                 # 结构/窗口/validate/zip↔磁盘
$V -c "from pathlib import Path
from career_sim_runner.validate import validate_submission
r=validate_submission(Path('<pkg>'));print(r.ok)
[print(c.ok,c.name,c.detail) for c in r.checks]"
```

**期望**：过拟合 0 命中 ／ 硬门禁 `FAIL=0 WARN=0` ／ 官方 validate **3/3** ／ zip↔磁盘 ALL MATCH ／ 常驻层 ≤ 58,590 字符 ／ CRLF = 0。

> **validate 3/3 只证明格式合法。** 它不验证策略、不验证分数、不验证过拟合。

## 6.7 反过拟合的代价（唯一一次实测）

`nofit 变体` 跑 dev 得 **69.96 / B / L5**；基线 qe24 得 **78.96 / A / L6** ⇒ **−9.00**。

六维归因 = **三处各 −3.00**（职级/财富/同事关系），专业/身心/风控**完全打平** ⇒ **引擎机制层没被削弱**。

根因链：M12 差 **1 点 O**（O=4 vs 门槛 5）挂窗 ⇒ L4@M24 而非 M18 ⇒ L6 物理不可能；再加 M36 差 1 点 S。

三条不确定已明示：**只有 1 局**；有混淆变量（同时改了 M6 ④）；输入词元降了 20%。

> 后面 r5 跑到 78.29 —— **我们没把这说成"反过拟合不亏"**，因为 n=1 对 n=1 定不了论（见 [05 §5.4](05-策略演进-v54到v70.md#54-最后为什么选-r9)）。

## 6.8 可迁移的五条

1. **先定义"过拟合"的可计算度量**，再做减法。我们用了三个指标（选项原文 / 事件标题 / 正文占比），都能一行命令复现。
2. **逐字匹配一定不够**，补 8-gram；8-gram 也不够，补人工形态层。
3. **删 dev 内容的时候，优先删"数值、统计、事件名"，保留"方向、机制、排序"** ——  directing > 数值。
4. **任何硬编码的表都要挂"发现表失效"的保险丝**（SAT），否则表错了你永远不知道。
5. **删完之后要能证明机制层没被削弱**（六维逐项归因，而不是看总分掉了多少）。
