# 07 · 工程与跑局复现

> 想真的跑一局？先读这篇，能省你两个晚上和一次 ¥9。
> 一局的量级：**约 2,400–2,500 次工具调用 / 195–196 回合 / 28–47 分钟 / 30–41M input token / ¥4.5–9**。

## 7.1 一局是怎么跑起来的

```
                 ┌─ 起引擎（jiuwenswarm-start --name career_emu app）
                 │     ⚠️ 端口由实例分配、会漂移（19092 → 20092 都见过）
                 │
发局 ────────────┼─ 探测端口（最多 30 × 1s）
                 │
                 ├─ play --submission <pkg> --ws-url ws://127.0.0.1:<PORT> --timeout-s 86400
                 │     PYTHONPATH=/tmp/shim_off  pythonw.exe -m career_sim_runner play ...
                 │     ★ pythonw.exe + & + disown ⇒ 脱离本终端（防整体回收）
                 │
                 └─ 读分：轮询 score_report.json（每 20s，最长 3h）
                        等不到 ⇒ 降级用离线兜底算分（见 §7.4）
```

产物落在 `.career_sim_runner/career_emu/outputs/<agent>/<UTC>/`：`score_report.json`、`events-*.jsonl`、`timeline.csv`、transcript。

## 7.2 三步加固（v69 局的教训）

v69 那局在 **M48 最后 2–4 个调用被外力猝死**，`score_report` 没写出来。后来发现那是另一个 bug（§7.5），但加固本身留下了：

1. **play 进程脱离本终端**：`pythonw.exe`（Windows GUI 子系统，无控制台句柄）+ `&` + `disown`；
2. **读分「等报告 → 降级兜底」**：轮询 `score_report.json`，等不到就调离线算分器给**带区间**的分；
3. **每步超时/失败退出口**，不留悬挂。

外加一条：**只认发局时刻之后写出的报告**（`PLAY_EPOCH=$(date +%s)` + `getmtime > PLAY_EPOCH`）——这是 v67 旧报告事故的教训。

## 7.3 环境纪律（踩过的）

| 坑 | 现象 | 解法 |
|---|---|---|
| **端口漂移** | `engine FAILED` | 先 grep 实际端口，再改等待窗口。**别信写死的 19092** |
| **代理拦 ws** | 校验写出失败 | 跑之前 `unset` 所有 `*_PROXY` + `export NO_PROXY=127.0.0.1,localhost` |
| **计划任务下 stdout 是 GBK** | `print('\ufffd')` 抛 `UnicodeEncodeError` | `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1` |
| **僵尸 `.instance.pid`** | PID 复用误报"进程还活着" | 先探端口，在听就跳过，否则 `DeleteFileW` 删 pid |
| **safe-delete shim** | `os.remove` 被改道回收站并 fail-closed | `python -S` / `PYTHONPATH` 置空 shadow / `ctypes.windll.kernel32.DeleteFileW` |
| **后台任务 19 分钟被回收** | `run_in_background`、`nohup`、`CREATE_BREAKAWAY_FROM_JOB`、`DETACHED_PROCESS` **全都不行** | 只能用 **Windows 计划任务** |
| **genie-trash 报 "aborted"** | 报错 ≠ 失败，文件其实已经删了 | 用 `ls` 复核，别信退出码 |

## 7.4 离线算分体系（零成本，比跑局重要）

| 脚本 | 干什么 |
|---|---|
| `_offline_baseline.py` | **离线基线盘点**：从历史 `events-*.jsonl` 直接算「工具调用画像」（动作/读文件/grep/观察/skill 五分类，按 `tool_call_id` 去重——同一次调用会有两条：一条 `delta_kind=custom` 增量版） |
| `_offline_score_latest.py` | **通用兜底算分**：取最新一局 jsonl 最后一行的 `payload.raw_output.result` → 重建 `CareerState` → 调引擎**自己的** `EndingScoreLoader + EndingScoreCalculator` 算官方口径分。`hidden_risk` 不可见 ⇒ 扫 R=0..4 给**敏感度带** |
| `_v69_offline_score.py` | v69 专用版（硬编码终态，扫 R=0..4）：v69 局在 M48 被猝死时的**下界** |
| `_offline_hangwin3.py` | 挂窗根因离线分析（21 局封顶已生效样本） |
| `play_shadow_rules_v3.md` / `v4.md` | **影子测试器报告**：零成本回放 play40/41/42（v3 可配 419 决策 / v4 560 决策），按「终局悬崖项 + 晋升进度项 + 按剩余月折现」估值，**逐门消融**（HD / HD44 / WIN / S0 / NEG） |

**为什么这套比跑局重要**：v60r-qe4 那次花钱跑了一局才发现「索引能省往返」这个假设是错的——**其实历史局里就能先算出来**。离线基线是免费的，跑局是贵的。

**口径互证**：v69 离线算得 74.25(R0)/73.25(R1)/72.25(R2)，与 v67 报单 `59.77 × 0.7 = 41.84` 交叉验证出 `competition_quantitative_weight = 0.7`。两套口径必须互证，否则离线分是假的。

**离线 vs 付费**：离线给的是**下界**（缺尾调用），所以按**上带**报。

## 7.5 🔴 那个"猝死"的真凶

**现象**：v70-r2 局 24 分钟崩于 **M42 季度体力分配事件**，未跑满 48 月，无 `score_report`。

**取证**：Agent 提交组合多选 `choice: [6, 3, 3]`（健康恢复 + 人脉维护 ×2）。
战报镜像 `career_sim_runner/replay/parse.py:121` 用 `int(choice)` 解析 ⇒ list 直接 `TypeError` ⇒ **带崩整个 play 进程**。

**关键定性**：**引擎收到的是完整 list、动作执行成功了，崩的只是战报镜像。**

**回溯**：v69 那次「M48 被猝死」**是同一个缺陷**（v69 死 M48、v70-r2 死 M42，都是季度体力多选帧），当时误归因为外力。

**修复**（本地工具，不属提交件）：`parse.py` L124–125 列表取首元素容错。修复后 pytest **59 全过**。

> **教训**：看到"进程死了"，先怀疑**解析层**，再怀疑运气。我们在这上面浪费了整整一个版本。

## 7.6 跑一局的最小步骤

```bash
cd <workdir>
export NO_PROXY=127.0.0.1,localhost
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy ALL_PROXY all_proxy

bash run_game_v70.sh        # 6 步：自检 → 冲突审计 → shim → 清 marker → 起引擎(探端口) → play → 读分
# 端口漂移之后：
bash _run_v70_now.sh        # 显式端口 / 等待窗口 240s / 轮询 score_report 90 min
```

**时长**：约 30–47 分钟 ｜ **产物**：见 §7.1 ｜ **遥测**：`_offline_baseline.py 20` 可从 jsonl 算调用画像（零成本）。
