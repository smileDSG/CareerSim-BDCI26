# 08 · 关键战役复盘

> 六个案例，每个都是同一个格式：**现象 → 取证 → 归因 → 修法 → 教训**。
> 按"学到的东西值不值钱"排，不是按时间排。

---

## 战役 A：v63 崩盘（14.73 / E 级 / 24 月出局）

**现象**
10/03 跑 v63/v63b，结果 `quantitative=14.73`、`competition=10.31`、**E 级、`outcome=eliminated`、survival 24 月、全程卡 L1**（level=1.0、S9、N2）。
`play_exit_code=0`、`termination_reason=None` —— **它是正常跑完的，不是崩溃**。

**取证（引擎级，逐条对账）**

1. v63 改动①把「已达门槛、未满 cap」那一档从**门票价**（`+3 ÷ 缺口`）砍成**常规单价**（S 0.125/点）——**降约 24 倍**；
2. ⇒ L1 / L2 的边际晋升激励归零 ⇒ Agent 只守不进；
3. L1 的 **N cap = 3** ⇒ perf 的 `min(S, N)` 结构被锁死 = 3；
4. ⇒ 半年绩效 ≈ 2.5 < 4；
5. M6 / M12 靠 mercy 抬到 4 能蒙混，**M18 / M24 mercy 已失效**；
6. ⇒ 「连续两次半年 perf < 4」hp=2 耗尽 ⇒ **炒鱿鱼**。

**修法**
回退三层计价，恢复「补缺优先」的门票价；并把这条写进包里：**L1 不能熬**。

**教训**
> **「慢慢攒、不急升」在一个带半年考核的引擎里是数学死路。**
> 更通用的那一条：**任何"把某区间的边际收益改成常规价"的改动，都要先问它会不会把下游的某个硬约束饿死。** 我们当时只算了自己那一格，没算 perf。

## 战役 B：「猝死」的真凶是 runner，不是运气

**现象**
v70-r2 24 分钟崩于 M42；v69 崩于 M48。当时两份报告都写成"进程被外力杀掉"。

**取证**
看 `replay/parse.py:121` → `int(args.get("choice", 0))`。
Agent 提交的季度体力是**多选**：`choice: [6, 3, 3]` ⇒ list ⇒ `TypeError` ⇒ 带崩 mirror ⇒ play 进程死。
再看引擎侧：动作**已经执行成功**了，死的只是战报渲染。

**归因**
同一个缺陷的两次发作（M48 / M42 都是季度体力帧）。第一次归错了因。

**修法**
`parse.py` L124–125 列表取首元素容错；pytest 59 全过。

**教训**
> 进程死了 → **先看解析层，再看运气。**
> 这条我们后来直接写成了纪律：**任何"崩溃归因为外部因素"的论断，必须先排除自己的代码路径。**

## 战役 C：60K 截断 —— 指针到了，目标没到

**现象**
qe21（10/02）：SKILL 63,888 字符，被切 4,799 字符 / 76 行。切掉的内容里包括 **`## 常驻红线`（整节）** 和 **`## 附录索引`（整节）**。

**取证**
- 包开头有一张**阅读路由表**（在送达区），明写"红线看 §3 + 文末常驻红线"；
- 而"文末常驻红线"这一节，**从来没有一次进过上下文**。

**归因**
不是"少看了点内容"，是**兜底机制的双重失效**：① 指针到了目标没到；② 丢的恰恰是只在坏局才用得上的兜底。

**修法（两阶段）**
1. 一次性：把内容外置到 `references/`（按需加载）——**只顶住三版**；
2. 结构性：把常驻层压到 58,590 字符以内，每版打包前重算窗余。

**教训**
> **"外置"是一次性节食，不是结构性修复。**
> 第二个教训更狠：**你的文档里有"指针"，你的上下文里必须有"目标"，否则指针比没有指针更糟**——它会让 Agent 确信自己读过某段规则。

## 战役 D：v71 零垫维护维律（168 回合逐手对账）

**现象**
v70 上一局（68 回合）里，三次挂窗（M6 / M12 / M18）**死法完全一样**。

**取证**
逐手对账发现：
- **L1 的 N `cap` = 门槛 = 3**（缓冲 0），顶满也只刚好达标；W−1 月被剧情事件打 N−1 / N−2 就挂；
- 三个"出事前"的月份，**energy 都是 0**；
- 零垫维顶满被打率：**N 24%**（38 手 9 次）/ O 9%；**W−1 月 N 44%**。

**再挖一层，得到引擎事实**：
> 能量只在 **3 的倍数月**发放、当回合分配完、**不累积**；而 W−1 = M5 / M11 / M17 / … **都不是 3 的倍数**。
> ⇒ **零垫维在 W−1 被打，没有任何补救手段**，只能在「选」这一层防。

**修法**（197 字符，L186）
L1 的 O·N 在 W−3 ~ W−1 **恒按贴线门槛维保护**，不因"已达标"或 v54「须为唯一未达门槛维」收窄而失保护；**禁止文本判向对该维下正向预测**；只排序不删项 ⇒ 死锁 0。

**零过拟合保证**
无事件名 / 选项 / 数值，依据全是**引擎结构**（cap=门槛 ⇒ 缓冲 0 ／ 发放月 ≠ W−1 ⇒ 不可补 ／ 判定取 W−1 月末）。

**教训**
> **"顶满就安全"是幻觉。** cap = 门槛时缓冲就是 0，而"顶满"这个动作本身不会给你任何额外抗打能力。
> 也顺带暴露一类问题：**规则有，但没被**——M17 Agent 自己判「#1 护 N」，实际选了 N−1，违反了 §2.3c 硬边界。

## 战役 E：过拟合审计的洞（精确层 0% ≠ 干净）

**现象**
r6 的过拟合审计显示精确层 0.0%，我们差点宣布"干净了"。

**取证**
换了个思路：不再只看整条命中，而是把 dev 语料切成 **8-gram** 跟包内做**逐行交集**。扫出 8 处：

- `SKILL.md` §2.3 那张「关键词 → 平均 S 系数」表（**10 个数值，典型数值型拟合**）；
- 3 处 `ref-*` 里的 dev 选项原文 + 精确 Δ；
- 1 处事件名 + Δ；
- `design/packaging-discipline` 3 处。

**全部是 v62 前的历史遗留。**

r7 又扫出 5 处（自动层够不着的"取证案例式引用"：run id、链名、选项原文）。

**修法**
删 dev 身份（事件名 / 链名 / run id / 选项原文 / 精确 Δ），**规则本身一条没动**。

**教训（两层）**
> 1. **逐字匹配对"截短 2–5 字"完全无感。** 必须补 8-gram 模糊层，再补人工形态层 grep（事件名 / run id / 选项引号 + 数字）。
> 2. **历史债会在你以为清完的时候冒出来。** 每改一版都要重跑全套，不能只跑新增部分。

## 战役 F：r5 的 78.29 vs r8/r9 的 61.3 —— 我们**没有**给出结论

**现象**
- r5（10/04 23:38）：**78.29 / A / completed / 48 月 / `play_exit_code=0`**，第一次拿到完整 `score_report`；
- r6/r7 的验证局（10/05）：**61.3 / B / L4**，M24/30/36/42 连续挂窗（CAP-SNAP 在 L4 出现 64 次）。

差 **17 分**。

**我们做了什么**
**什么都没宣布。**

**为什么**
n = 1 对 n = 1。三个归因候选都还活着：

| 候选 | 依据 | 反证风险 |
|---|---|---|
| ① dev 清理的代价 | `§2.3` 那张「关键词 → 平均 S 系数」表（10 个词）是本地选高 S 选项的主力依据；朋友的实测同形（反过拟合后 74.23 → 66.75） | 同版本对照没有 |
| ② 单局方差 | 早期同 SKILL 五局：79.38 / 84.22 / 77.22 / 76.35 / 71.42，**区间 71–84** | 完全够解释 17 分 |
| ③ 环境差异 | 端口漂移、实例陈旧、token 异常都有过 | 无法排除 |

**要拆开必须**：再跑**同版本相邻局各 2 局**。赛期截止，没跑到。

**教训**
> **归因纪律 `n=1 不许定论` 是这次比赛最贵的习惯**（贵在会让你放弃一个真发现，但便宜在不会让你拿一个假结论去 next 版本）。
> 顺带一条：**r6/r7 从未跑局** —— 它们的分数只能当 r7 的**近似上界**，这个必须在文档里写明，不能让读者以为 r9 跑过局。

## 六条共性

| # | 共性 | 一句话 |
|---|---|---|
| 1 | **现象 ≠ 成因** | 三次"进程被杀"里，两次是我们自己的 runner |
| 2 | **归因先排除自己** | 归因为"外部因素"之前，先穷举自己的代码路径 |
| 3 | **指针 ≠ 内容** | 文档里写了"看文末红线"，不等于红进了上下文 |
| 4 | **顶满 ≠ 安全** | cap = 门槛时缓冲就是 0 |
| 5 | **0% ≠ 0** | 精确层 0% 的时候，模糊层可能刚扫出 8 处 |
| 6 | **差异 ≠ 因果** | 78.29 vs 61.3 中间隔着一个 n=1 |
