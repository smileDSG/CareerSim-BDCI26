# 决策报告：从关键词 proxy 到 LLM Agent

> 📦 **本包版本：v60r-qe26-20261003**（由 `_stamp_versions.py` 内嵌，取自 `_build_pkg_v57.py` 的 `TAG`；勿手改）

## 1. 问题定义

在 CCF BDCI 2026「Agent 职场长程生存与晋升」赛题中，Agent 每月面对剧情事件，只能读到**叙事文字**（`obs.choices` 仅含 `action` + `description`），数值后果完全不透传。目标是在 48 个月内存活并尽量晋升。

核心难点：**事件抉择层必须在"读文字 → 推断后果 → 选最优"上做对**，而后果对 Agent 不可见。

## 2. 探索过程

### 阶段 A：占位事件池（错误基准）

官方 `action_pool` 未发布时，用占位池自测。此阶段一切"随机性导致月 6 逃不出 L1"的判断**是误判**——占位池机制与官方不同，结论不可信。

### 阶段 B：官方 dev 数据接入

定位并克隆真实数据集 `Flash-Tomato/CareerEmuData-Dev`（dev8 包内写死的 `TomatoEmuData-Test` 已 404），将 171 个真实事件填入引擎 `data/dataset`。用真实事件池跑出**首个真·结果**：月 10 `wealth_deficit` 出局。

### 阶段 C：关键词 proxy（被否定的投机方案）

把事件抉择实现为 `cor_event_policy.py`：用中文正负词典（`text_to_deltas`）从叙事文字**反推**各资源影响，再按 COR 打分选最优。迭代中挖出两个根因级 bug：

- **风险符号 bug**：风险增加词误放"减少"词典，使风险项反得 +5 奖励 → 隐患累积爆雷。
- **报销做假账陷阱**：叙事"把账做平**报销**"看着像收入，实为 `hidden_risk+2`；proxy 把"报销"当财富+，疯狂踩雷。

修复后，财富/健康死亡清零，但 **8 局扫描 0 存活**，死因**统一为"两次半年绩效不佳"**——即月 6 谈话时 `O 没堆到 3 / H 没顶到 8 / R 没压到 0`。

### 阶段 D：根因诊断与转向

proxy 失效的本质是一个 **ill-posed 逆问题**：从文字反推引擎隐藏的数值 delta，而同一句话的机械效果可与字面相反，proxy 没有任何额外信号去判别。这**恰是比赛设计意图**——真实 Agent 必须是 LLM 驱动（JiuwenSwarm + DeepSeek V4 Flash 读文字推理），不是数值启发式。

**结论**：proxy 攒出的**领域知识有价值**（谈话公式、财富≈0、报销陷阱、健康螺旋、隐患爆雷），但**执行层（读文字选事件）不该由关键词 proxy 做**。正确做法是把领域知识写成 LLM 能读的说明书（SKILL.md），让会读文字的 LLM 决策。这也解释了后来实测到的"token 与成绩无正相关"——提分杠杆是**前置的知识注入**，不是现场的推理搜索。

## 3. 最终方案

- **交付物**：`solution/` 技能包 ——
  `manifest.json`（含 instruction 常驻策略指令，第十九轮起点名 cor-career / cor-window 两技能与加载时机，第二十一轮补入自走率/冻结闸/W−3）+ `skills/cor-career/SKILL.md`（主技能·判据层 769 行）+ `skills/cor-window/SKILL.md`（配套技能·调度层 197 行）+ `skills/cor-career/references/`（机制词典 + 6 张附录，共 546 行）+ `design/` 设计文档 5 份。
- **运行模式**：**`agent`**（长程规划契合 COR 长期保存资源内核）。
  ⚠️ 早期文档写的 `agent.plan` 是旧 runner 的 sub_mode 写法；现版契约 `SUPPORTED_RUN_MODES = {"agent","team"}`，
  server 日志实测 `sub_mode=None`，`manifest.json` 亦为 `"mode": "agent"`（详见 `framework_rationale.md` §1）。
- **策略内核**：四层——
  ① **三维均衡判据**（§2.2c：`μ = (eff − 现值)/eff` 定唯一目标维，剧情槽/主行动/体力共用）；
  ② **到 cap 硬闸 + 必写痕迹**（`CAP-SNAP / TARGET / PICK`，把"该维已满"钉成纸面事实）；
  ③ **窗口预算与能量预留**（§5.4 补缺压力 P + §5.1 M3 领的 3E 先划 2E 作下一窗口保险金）；
  ④ **否决优先级**（§3 红线 + 0a 真否决："保守优先于获取"）。
- **领域先验显式化**：把所有 proxy 阶段与真实对局中发现的隐藏机制（财富≈0、报销陷阱、健康螺旋、隐患爆雷、
  门槛全 `>=` 卡线能过、`eff` 饱和线、mercy 与奖金 C 档代价、`cumulative_risk_inverted`）直接写进 SKILL.md / references，
  LLM 无需从文字"悟"出，避免重踩。

## 4. 已知边界（诚实声明）

- proxy 阶段证明 COR 架构正确（favorable 样本曾月 6 逃 L1 活到月 14），但**未经真实 LLM 对局验证**。
- LLM 同样看不到数值 delta，仍需靠 SKILL.md 提供的领域先验 + 自身长链状态跟踪 / 多季 look-ahead 能力补足。
- 真实评分依赖 Test 剧本（保密），本地仅能跑 Dev 验证；最终成绩以官方 Test 评测为准。

## 5. 后续演化（本报告的延续）

本报告记录的是"从 proxy 到 LLM"的**方向性决策**；方向确定后，策略正文经历了 **10 → 18 轮**迭代
（每一轮都由真实对局或源码级审计驱动，且改动前先用离线回放验证）——完整证据链见
`skills_design.md` §9「十八轮迭代证据链」。其中与本报告直接呼应的是 **§6 的判据**：
既然执行层必须是 LLM，那么"让 LLM 现场多想"无用，真正的抓手是**把判据写成可以逐字执行的阶梯**——
这正是第十七/十八轮把固定维序改写成唯一公式 `μ`、并强制写 `CAP-SNAP/TARGET/PICK` 三行痕迹的原因。
