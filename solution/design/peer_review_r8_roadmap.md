## 1. 三条我们确实没有的机制（按决赛实施优先级排序）

### ① SAT 同局饱和标定 —— **最高价值**

他的做法：对确定性菜单动作做「动作前记录可见 x → 该动作明确承诺 +x → 执行 → 立刻复测 →
没涨就记 `x ∈ SAT`」，晋升后清空 SAT；**不为 SAT 中的维花能量**。

**为什么对我们重要**：我们的 `cap = int(门槛(L→L+1) × 1.2)` 是**写死的硬表**。
它在本引擎下已被验证正确，但它是**查表式结论**——一旦 Test 的 cap/门槛与 dev 不同，整张表连带失效。
SAT 是**机制层自标定**，不依赖任何数值先验 ⇒ 天然跨池。

**但直接照搬有风险**：他**没有** cap 表，SAT 是他的唯一依据；我们已有精确 cap 表，
再叠 SAT 会出现「双重压制」——若某维因随机/半年结算口径暂时没涨而被误记 SAT，
agent 会**提前停投一个真正需要的门槛维** ⇒ 直接挂窗。

**r8 的正确接法（交叉校验层，不是替代品）**：
- SAT **只**用于「能量/主动作的边际投放」，**永远不参与门槛达标判定**；
- 与硬 cap 表冲突时**以 cap 表为准**（延续本包「硬表族必须有具名例外」的纪律：
  这里是给 SAT 加具名例外，不是给 cap 表开口子）；
- SAT 触发需满足**双条件**（承诺 +x **且** 复测未涨 **且** 该维当前已 ≥ 本级门槛），
  避免把「还没到 cap、只是这手没涨」误判成饱和。

### ② 绩效恢复「实绩 ≠ 可见度」—— 防一类我们没覆盖的死锁

他的规则：绩效告警时只认**可见的、可归因的完成结果**（交付/修复/上线/被采纳/被认可）；
**纯汇报、材料准备、意图、申请、努力 ≠ 实绩**；「只提高可见度」的动作每个评审周期**至多一次**，
且必须在已拿到实绩之后，否则不解锁。

我们目前只有 §5.1 的 perf 公式与「D 跌破门槛必补」，**没有「别把汇报当交付」这条显式禁令**。
风险形态：D 偏低时 agent 反复选包装/呈现类动作，看起来在补 D，实际上 perf 没改善，还挤掉门槛维的能量。

🔴 **与既有条款的冲突（必须先裁决，否则上不了线）**：我们**已经把汇报当工具在用**，不是没用过——
`ref-5-promotion.md` L46 明文「**每季 ≥1 次汇报类保 `O ≥ 22`**（p44 死因）」，
`ref-quarterly-actions.md` L15 记 `prepare_report_material` = 1E → `O+1, D+1`。
⇒ 他的「可见度动作每周期至多一次」与我们的「每季至少一次」**在字面上直接冲突**。

**裁决**：两条管的不是同一件事——
- **他的**：管 **D / 绩效恢复**（别拿汇报冒充交付成果）；
- **我们的**：管 **O 门槛维护**（O 是恒最贴线的门槛维，L1/L2 的 O `cap == 门槛`、垫 0）。

⇒ 上 ② 时必须带**具名例外**：**② 只约束「为补 D / 绩效而做的呈现类动作」，
**不覆盖** `ref-5-promotion.md` L46 的「每季 ≥1 次汇报类保 `O ≥ 22`」**。
没有这条具名例外，② 会把一条有 p44 死因取证支撑的 O 维保命线给误删掉。

### ③ 安全合规 SAFE / OPEN / U 三态 —— 风控维的判据缺失

他的规则：对**越权取数、可能泄露、造假、欺诈、毁证、秘密外传、绕开强制管控**，
只问一句「这个动作是否留下已知可利用/违法敞口」：`SAFE`（根因已修或路径已堵）／
`OPEN`（敞口仍在，**含"仅监控"式处理**）／`U`（判不了）；有 SAFE 备选时**一律拒 OPEN**；
`ISSUE=OPEN` **不因 HR/系统的友好话术而关闭**。

⚠️ **修正先前的措辞**（原写"我们没有"，属**过度断言**，已核）：我们**已经有一条**——
`appendix-f-fewshot.md` L40：安全/合规类事件里「正式报告」= **止损清雷**，**不适用**对抗升级词表。
真正缺的不是这条，而是**三态判据本身**：**「仅监控」式处理仍算 `OPEN`**、以及
「有 SAFE 备选时一律拒 OPEN」的**选择规则**。⇒ ③ 的正确接法是**在既有 L40 例外条款上补判据**，
**不是新增一条平行条款**（否则立刻构成冗余 + 口径冲突）。风控维权重 0.10，且爆雷是全场最大单点损失，值得补。

## 4. 实施与验证纪律（决赛）

1. **一次只上一条**，顺序 ① → ② → ③；每条都必须**同版本相邻局对照**（只同版本相邻局可比）。
2. ① 的验收指标不是总分，而是：**挂窗次数是否增加**（若 SAT 误判，挂窗会立刻上升）。
3. ② 的验收指标：perf 告警期的**实绩动作占比**与 D 恢复速度。
4. ③ 的验收指标：`R` 峰值与是否出现 `risk_burst`。
5. **任何一条若使挂窗 +1，立即回滚**——窗口事故是全局最大损失，优先级高于一切新增机制。
