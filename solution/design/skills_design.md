## 1. 赛题约束（决定了全部设计的形状）

| 约束 | 事实 | 对设计的直接影响 |
|---|---|---|
| 信息不对称 | `observe` 只返回选项的**叙事文字**，不带任何数值后果 | 决策层必须是会读文字的 LLM，不能是数值启发式（见 §6、`decision_report.md`） |
| 回包极简 | `take_action` 只回 `{success, error}` | 账本唯一真源 = `observe` 的 `current_state.status`，必须前后快照对账 |
| 带宽上限 | 引擎 1.0.1 对每级 S/O/N 设 **`cap = int(门槛(L→L+1) × 1.2)`**（＝「本级自己的晋升门槛」×1.2），结算后强制钳回（D、H **不钳**） | 到 cap 后增量全蒸发 → **晋升是唯一解锁手段** |
| 评分饱和线 | 终局计分另有上限：**S 计入 120、N 计入 60，O 不计入终局分** | 「cap」≠「值得投的上限」→ 引入 **`eff = min(cap, 饱和线)`**（§3.1） |
| 时限 | 48 个月，8 个评审窗口；每 3 个月 1 次体力(3E)+1 主行动 = 全程 16 季 | 资源极度稀缺，必须按窗口做 6 个月跨度的预算 |
| 精力极大值 | 首次评审在 **M6**，而 `cap(L1) = 门槛(L2)` → L1 的 O/N **零缓冲** | 「顶满 cap」在 L1 字面等价于"刚好踩线" → 首年是全程最脆弱段 |
| Test 剧本保密 | 云端评测用未见过的事件剧本 | 硬编码查表可能失效 → 通用规则必须占主导（§10.1） |

## 2. 理论根基：资源保存理论（COR）

Hobfoll (1989) 的核心命题映射到本赛题：

1. **损失厌恶**：资源损失的心理冲击远大于等量获得的增益 → 对应"爆雷 −5 分（永久）＋回滚 vs 晋升 +3 分"的不对称；
2. **资源稀缺时转向防御性保守** → 对应"挂窗可以接受，破底线不可接受"；
3. **资源保存优先于资源获取** → 对应否决闸（0a 真否决）优先于任何收益比较。

| 状态槽 | COR 角色 | 本方案定位 |
|---|---|---|
| R 隐患 | 负债型资源 | **唯一生死开关**：R≥5 触发 `risk_burst`（hp=2，第二次直接淘汰）；且爆雷次数**永不复位** |
| H 健康 | 底线资源 | H≤0 立即结束（0 分） |
| D 尊严 | 社交资源 | 晋升硬门槛 + 谈话公式权重项；**D≤1 连续 3 月 = `dignity_crisis`** |
| O 产出 | 绩效资源 | perf 除数项(÷10) + 每级硬门槛；**不进终局分** → 只服务于门槛与 perf |
| S 技能 / N 人脉 / W 财富 | 长期资源 | 受 cap 钳制，只能靠晋升解锁；S、N 是终局得分主项 |

## 3. 引擎机制实证（1.0.1 源码级，非推测）

| 机制 | 规则 | 对策 |
|---|---|---|
| **带宽钳制** | 每级 S/O/N 的 `cap = int(门槛(L→L+1) × 1.2)`（`game.py:347-355` 构造 `clamp_dict`，键 = `from_level`），`clamp_stats` 结算时强制钳回；**D、H 不在钳制列表**。⚠️ 注意两种常见说法**指同一个数**：「本级自己的晋升门槛」＝「下一级的准入门槛」（SKILL 正文用的是后一种措辞） | 到 cap 即停（§2.2c ③ 硬闸）；**安全垫 = cap − 门槛 = 0.2×门槛**，是被扣穿后唯一能扛的量（§3.1） |
| **perf 公式** | `perf = round((min(2·min(S,N), max(S,N)) + 0.3·max(0, S−2N))/15 + O/10 + poly(L))`，poly：L1 +2 / L2 +3 / L3 +2 / L4 0 / L5 −4 / L6 −8 / L7 −12 / L8 −16 / L9 −19 / L10 −27 | **S:N 守 2:1**；N 是 `min` 乘法短板，投 S 前先看 N |
| **半年奖金** | perf≥12→3.0× / ≥8→1.5×(A) / ≥5→0.5×(B) / ≥3→−1.0×(C) / <3→−2.0×(D)；**perf<4 连续两次 = 淘汰** | 守 B 争 A，不追 S 档（物理不可达） |
| **评审时点** | 进入评审月**月初**结算，用**上月末**状态（`game.py:_after_calendar_advance`：日历推进 → 半年谈话 → 薪水 → 晋升闸） | **评审当月补属性无效**，必须提前一个月末达标；**talk 的加成在闸之前生效**（good 档可得 perf+2/D+2/N+1） |
| **晋升闸** | `month % 6 == 0` **且** `duration_in_level ≥ 6`；`promotion_conditions.py` 的 optional 条件在源码里是**硬门**（`_conditions_match` 不满足即 return False） | 挂窗 = 后移 6 个月且**不解锁下一级带宽** → 级联（§5） |
| **晋升副作用** | `rapid_promotion`：距上次晋升 <12 个月 → 本次额外 `N−3 D−1`；叠加逐级自带 `stat_change`（L3→L4 N−2 / L4→L5 N−2 / L5→L6 N−3 / L6→L7 N−4） | **不能写"能升就升"**：每级实际付 N−2~−6，而 N 正是卡窗维；晋升当月即重算 N 缺口预算 |
| **半年谈话** | `talk = 3.5·perf + D + 0.25H − 2R − 4·burst − 0.8·D归零月数 − 3.0·连续差绩效`；good(≥35)→perf+2/D+2/N+1/R−1；bad(<20)→perf−2/D−2/R+1/H−1 | 谈话前顶满 D = good 档免费保险；`perf±2` 在每次评审后被清零（不累积） |
| **W 来源** | 月薪(level) + 半年奖金(perf档) + 事件 W 选项；**体力与主行动均不产 W**；L1 财富是 `apply_fractional_wealth` **定点累加**（每 3.33 月 +1 W），不是冻结 | 治 W 的药在晋升链上，不在 W 本身 |
| **评分权重** | level .30（每级 3 分）/ wealth .20（≤80）/ health+dignity .15（≤20）/ skill .15（**≤120**）/ `cumulative_risk_inverted` .10（≤10）/ network .10（**≤60**） | 见 §4.3 性价比总判据 |

### 3.1 新引擎独有、且最容易被写错的三件事（第十八轮补齐）

**(a) `eff = min(cap, 评分饱和线)`** —— 饱和线 = **S 120 / N 60 / O = cap**（O 不进终局分，故无独立饱和线）。

| 级 | cap S/O/N | eff S/O/N | 说明 |
|---|---|---|---|
| L1–L4 | 9/3/3 · 21/6/7 · 42/16/21 · 108/26/36 | **与 cap 相同** | 低段两线重合（所以低段的 cap 表没错） |
| L5 | 156/38/54 | **120**/38/54 | S 只认到 120 |
| L6 | 204/54/72 | **120**/54/**60** | S 与 N 都到线 |
| L7+ | 252/72/96（L8 300/90/120、L9 348/108/144） | **120**/72/**60** | 越往上 S 的"空气区"越大 |

⇒ 决策含义：**L5 起继续把 S 往上推过 120 是纯浪费**（L5 cap 156 里有 36 点是空气；L6 cap 204 里有 84 点）。**唯一例外**：L6/L7 的 S 门槛（170/210）高于饱和线 120，此时"门槛缺口"仍必须看（`eff` 不可用于比较门槛）。

**(b) 失败条件一共 7 条**（不是 3~4 条），每条都有 hp 计数：

| 失败条件 | 触发 | hp |
|---|---|---|
| `risk_burst` | R ≥ 5 | 2 |
| `health_zero` | H ≤ 0 | — |
| `dignity_crisis` | **D ≤ 1** 连续 3 个月（**D=1 也算**） | 2 |
| `network_isolated` | N ≤ 1 连续 3 个月 | 2 |
| `wealth_deficit` | W ≤ 0 连续 3 个月 | 2 |
| `skill_obsolete` | S ≤ 0 | 5 |
| `consecutive_bad_performance` | perf < 4 连续两次 | 2 |

**(c) 首年 mercy**：`current_month ≤ 12` 且 `performance_score < 4` → **强制 perf = 4**（`data/dataset/performance_score/config.data`）。
⇒ **M6/M12 的 perf 门物理上挂不了**（连 bad talk 的 −2 都被拉回 4）→ 首年真正的风险只有「O/N 被事件打穿」与 `duration_in_level`；代价是 **perf=4 落在奖金 C 档（−1.0×月薪）**，所以"护住 perf"的理由从"防挂窗"改为**"防倒扣"**。

## 4. 策略骨架：三维均衡 + 补缺压力

策略由两块咬合而成，分别解决"往哪走"和"什么时候发现走不动"。

### 4.1 三维均衡（解决"往哪走"）—— 第十八轮口径

> 早期版本是**固定维序 `O → N → S`**，且明文"禁止算缺口比大小"。这是错的：判据丢了量级——「O 缺 1 点」与「S 缺 66 点」在阶梯里完全等价，O 永远先赢（play43 实测：L4 段 N 恰好顶满 cap 36，而 S 83 只到 cap 108 的 77%）。

**"均衡"的正确定义不是三者平权**。按逐级增量需求加总：**S 204 / N 72 / O 54（合计 330）→ S 占 62%、N 22%、O 16%**。
⇒ **S 是总量主线（剧情槽长期押它）；O、N 是窗口保险（总量小，但安全垫只有 0~3 点，一碰就破）。**

每 6 个月重复同一循环：

```text
① 求出唯一目标维 μ（公式见 §4.2）
② 全部弹性资源对位补该维（主行动 > 体力 > 剧情槽，三者共用同一目标维）
③ 窗口前 1 个月末确认：三维 ≥ 门槛，且尽量顶到 eff；D ≥ 门槛；R = 0
④ 晋升 → cap 抬高一档 → 数值继续涨（+3 分/级）
⑤ 余量只投 H+D（且仅 H+D < 20 时）＋ 守 R=0 —— 🚫 绝不投 W
```

**⚠️ 第十八轮修正**：早期文档把「三维顶满 cap」写成"唯一安全姿势"。这不准确——因为 `cap − 门槛 = 0.2 × 门槛` 是**唯一余量**，而事件一轮就能磨掉好几点：

| 级 | 安全垫 = cap − 门槛（S/O/N） |
|---|---|
| L1 | **1 / 0 / 0** ← 零缓冲 |
| L2 | 3 / 1 / 1 |
| L3 | 7 / **2** / 3 |
| L4 | 18 / 4 / 6 |
| L5 | 26 / 6 / 9 |

⇒ **「顶满 cap」= 刚好踩在门槛上方 0~2 点**（L1 的 O/N 是 0），**只保证"刚好过门槛"，不保证"扛得住窗口前月的扣分"**。而钳制**只降不升** → 被事件打掉后必须**主动补回**。这条是 play43 单点级联（M6 挂窗 → L4 晚 12 个月 → −13.8 分）的算术解释。**结论：安全垫应当被当作"可动用预算"来花，而不是"必须保住的目标"。**

### 4.2 唯一判据：归一化缺口率 μ（解决"补哪一维"）

```text
μ = (eff − 现值) / eff          ← 跨维可比的归一化缺口
a) 任一维 < 门槛 → 目标维 = 这些维里 μ 最大者      （救窗口，压过一切）
b) 否则未满 eff 维 → 目标维 = μ 最大者
c) 全满 eff      → 无目标维 → 转 H/D → 最低代价项
并列固定取 N > O > S（N 是 perf 的 min 短板）

剧情槽 / 主行动 / 体力 —— 三者共用这一条判据（旧版"两套口径勿混"已废除）
目标维 → 附录：O→C / N→D / S→A
目标维 → 主行动：O→apply_key_project / N→build_mentorship / S→apply_rotation
目标维 → 体力  ：O→prepare_report_material / N→network_maintenance / S→skill_learning

⚠️ 窗口前月 W−1 专属修正：把 a) 档的「门槛」临时换成「门槛 + 3」
```

**为什么废除"两套口径"**：同一局并行两套判据（剧情槽走固定阶梯、主行动走缺口率）是幻觉温床，也是"S/O/N 地位不清"的直接来源（第十七轮定位到的三处结构性病灶之一）。

**到 cap 即停硬闸（③）**：已满 eff 维的 `+X` 一律按 **0** 计价；唯一正增益落在已满维的选项 → **禁选**；`S+2 O+2` 在 S 满 / O 缺时按 O+2 计价、照选；`S+2 O−1` 在 S 满 / O 缺时记 O−1 → 净负跳过。**并强制在每次 `take_action` 的 `notes` 里写出 `CAP-SNAP / TARGET / PICK` 三行**（缺一视为未按 SKILL 执行）——把"该维已满"钉成纸面上无法回避的事实，之后若仍选只给该维的选项，就是**可自查的自相矛盾**，而不是"判断失误"。

### 4.3 性价比总判据（每个选择前的统一标尺）

| 用途 | 边际价值 |
|---|---:|
| 风险清零（每 −1 R） | **1.00 分 + 保命**（最高优先级） |
| 身心维持（每 +1 H+D） | 0.75 分（按**最终值**结算 → 中前期是加减分项，月 44 起才是结算线） |
| 晋升（每级） | +3 分 + 抬高 cap |
| 财富（每 +1 W） | 0.25 分（无主动作来源） |
| 未满 **eff** 的 S / N（每 +1） | 0.125 / 0.167 分 |
| **已满 eff 的维度**（S>120 / N>60 / 超 cap） | **0 分** |

> **底线只有三条**：爆雷 / H 归零 / D 跌破 1（`dignity_crisis`）。其余全部是"账"。
> 把账当底线会误杀大量更优选项——三局 419 决策点回放实测折损 **51.5 分**。

### 4.4 补缺压力 P（解决"这窗放不放弃"）

```text
M = 下一窗口月份 − 当前月；Q = M ÷ 3（剩余主行动次数）
gap = 目标维门槛 − 当前值
可得增量 ≈ Q×2（主行动）+ Q×1（体力）+ 事件自给量
事件自给量 = λ_v × M（λ_v = **本局实测**事件自给月均斜率，算法见主技能 §2.2c ②第1.5步；
  ⚠️ 旧写死先验「S≈+8/窗，N≈−2/窗，O≈+3/窗」已被五局 35 窗样本证伪——
  N 方向完全相反（实测 +6.2/窗）、S 低估 2 倍（实测 +15.6/窗），一律禁用，只算本局实测）
P = gap ÷ 可得增量
  P ≤ 0.9  → 正常对位补
  P > 0.9  → 该窗注定挂：立即按新窗口重做预算（Q 重置），禁止自暴自弃转投 0 分维度
  （🧊 P>0.9 的维同时会被「冻结闸」从资源池剔除，见 §2.2c ②第1.5步；全维被剔 → 投 P 最小者）
```

⚠️ **μ 与 P 明确分家**：**μ 定"先补哪一维"，P 定"这窗放不放弃"**。play40 的三次挂窗（M18 差 2N/3O、M30 差 S27、M42 差 S6）**全部源于预算做晚了**（第十一轮才把预算提前到晋升当月），无一例是 perf 卡线。

**一致性的保证机制**（长期规划不跑偏的关键）：

1. **每个窗口的判定标准同一套**：三维 ≥ 门槛（尽量到 eff）、D ≥ 门槛、R = 0；
2. **预算在晋升当月就做**，而不是窗口临近才做；
3. **挂窗不等于改道**：挂窗后立即按新窗口重做预算（Q 重置为 6），禁止自暴自弃转投 0 分维度；
4. **终局口径有明确生效边界**：只在最后一个可达窗的评审结束后生效（play41 提前套用 = −3 分）。

### 5.1 能量必须为「窗口前月」预留（第十七/十八轮新增，被低估最久的一条）

实测机制：**每 3 个月发 3E**（M3/M6/M9/…，上限 3，不累计）；**`1E = 门槛维 +1 点`**（主行动 `准备汇报材料`→O+1、`人脉维护`→N+1；`技能学习`→S+1，**花费 2E**）。四局 12 次实测一致。

**关键约束**：窗口月 W 的判定在 **W 月初**、读 **W−1 月末**状态；而**前一次发能量是 W−3，W 自己那份发在判定之后 = 救不了**。
⇒ **要在 W−1 有能量可修门槛维，只能在 W−3 那次预留。**

**四局实测的代价**：**M5 全部 E0**（M3 领的 3E 在 M3 就花光，其中 2E 喂了 H）——这就是 p42/p43 M6 挂窗的直接可操作根因（p43 原文自证 `O 将由 3 降到 1…需在 M6 窗口前补回 O`，但它 M5 一分能量都没有）。

⇒ **落地条款**：每次领到 3E，**先划 2E 作「下一个窗口的保险金」**，仅当某门槛维 < 门槛 时才允许动用（非门槛维 H/D 仅当 H ≤ 6 即 hp 告急时才可动）；剩余 1E 才用于常规维护。

**诚实收益估计**：修好能量预留 → M6 首升提前 6 个月（四局 2 局命中）→ 逐级传导可能多 1~2 级 ≈ **+8~14 分**（量级项）。**救不了**的是：M5 抽到"两选项必伤一个门槛维"的长链且当级缓冲为 0 的硬死局，以及 L4→L5 的 S 产能上限。

## 6. 为什么执行层必须是 LLM（关键词 proxy 为何被否定）

早期尝试过 `cor_event_policy.py`：用中文正负词典从叙事文字**反推**数值 delta 再打分。它挖出了两个根因级 bug（风险词典符号反了、"报销"被当成财富+实为 `hidden_risk+2`），但最终 **8 局扫描 0 存活**。

失败的本质是一个 **ill-posed 逆问题**：同一句话的机械效果可以与字面相反（"把账做平报销"看着像收入，实际是埋雷），proxy 没有额外信号去判别。而这正是赛题的设计意图。

**结论**：proxy 攒出的**领域知识有价值**（谈话公式、财富≈0 陷阱、健康螺旋、隐患爆雷），但**执行层不该由它做**。正确做法是把领域知识写成 LLM 能读的说明书（SKILL.md），让会读文字的 LLM 决策——这同时解释了为什么 token 投入与成绩无正相关（n=33，r = **−0.360**，见 `token_analysis.md`）：提分杠杆是**前置的知识注入**，不是现场的推理搜索。

## 10. 已知边界（诚实声明）

1. **Test 剧本保密**：SKILL 中附录 A–F（现已外置）共 234 条硬编码事件条目与 §2.4d 的 11 条长链均来自 Dev 事件池，在 Test 上可能命中不到。因此通用规则（§2.2 判定阶梯、§2.2c 三维均衡、§5.4 补缺压力、§3 红线）被刻意放在决策链最前，查表降级为"命中才用"的参考——这也是第十六轮把附录外置的技术动因（见 `skill_architecture.md` §6）。

3. **首年 mercy 的下行风险**：mercy 把 perf 抬到 4 ⇒ 必然落 **C 档 −1.0×月薪**。首年"护住 perf"仍值得做，但**理由从"防挂窗"改成"防倒扣"**。
4. **影子测试的已知盲区**：oracle 以"R 门是全局基准"为假设，该假设本身无法自检。
5. **仍存不足且已披露**：`teammate_package/` 为旧版（md5 `c41cb5ecb204`），**本轮按指示未同步**；双技能拆分（`cor-career` 判据层 + `cor-window` 调度层）已落地并由冒烟局验证加载行为（`skill_architecture.md` §5）。
6. 本地评分为 Dev 口径，最终成绩以官方 Test 云端评测为准。
7. **`μ` 判据的一处已知边界（已量化，暂不改）**：L5/L6 段 S 的**门槛（130/170）高于其评分饱和线（120）**，故 S 落在 **[120, 门槛)** 区间时，`eff` 口径下 μ = 0、会在 a) 档（救门槛）排序里被排到最后。四局 **196 个可判月份**的离线回放（`_eff_replay3.py`）中该情形出现 **6 次**（p40 M41/M42/M48/M49、p42 M48/M49）——但这 6 个月里 **O 的 μ 同时更大、`cap`/`eff`/`门槛` 三种分母给出完全相同的选择 → 实测零影响**。因此按"改动必须数据驱动"的纪律**保留为观察项，不作改动**；若未来出现真实失分，最小修法是把 a) 档的分母换成**门槛**（回放显示该变体仅多改变 1 个月的选择）。
