> **总原则**：任何一层的失败都**不改 §3 红线**（爆雷 / H 归零 / D 跌破门槛仍是绝对底线），也**不许自暴自弃转投 0 分维度**（play39 连投 7 季追一个到不了的目标，全部蒸发）。恢复后**必须重做一次 cor-window §5.4 缺口预算**——因为时间已经过去了，Q（剩余主行动次数）变小了。

| 故障层 | 现象 | 恢复动作（按顺序） |
|---|---|---|
| **① 动作层** | `take_action` 回 `{success:false, error}` | 1) **先 `observe` 验账本**（有可能已部分生效，别急着重发）→ 2) 未生效则**重试一次同一动作** → 3) 仍失败则**换等价动作**（如同为补 N 的其它选项）→ 4) 都不行就**跳过本槽继续下一月**。空转一槽 ≈ 少 1 次事件收益，远小于卡死整局 |
| **② 账本层** | delta 与预期不符 / 记忆里没有某维的值 | **一律以 `observe` 回包的 `status` 为准，禁止凭记忆或笔记推断**（§1.1 防幻觉硬规则）。🚨 **对账必须对照本文件原文**——play41 教训：匿名反馈链自称"按表否认"，实为承认链正解，两次误判 = 两个 R+2 黑洞。**别采信自己的笔记** |
| **③ 局内层（灾难）** | 已爆过一次雷（**hp 只剩 1，再爆即淘汰**） | 立即进入**存活模式**：`R 归零` 优先于一切晋升预算，本季 `defuse_legacy_risk`(2E) + 主行动 `lay_low`（每季最多 −2R），**拒绝任何带风险意象的选项**，直到 **R=0 连续两个窗口**才解除。此时少升一级（−3 分）是划算的，第二次爆雷（直接淘汰）不是 |
| **④ 运行层** | 上下文被压缩 / 续跑指令 / 思考超时 | 用 `session_id` + `observe` + `check_latest_logs` **恢复账本，不重建**（账本真值本来就在 `observe` 里，不依赖对话上下文）；超时则保留 SKILL 调用、去掉长推理——**策略正文不依赖规划层**，独立可读可执行 |

**降级顺序（资源紧张时的取舍）**：`保 R=0` > `保 H>0 / D≥门槛` > `保下一窗硬门槛维` > `补 H+D 到 20` > `追 W / 追已封顶维`。
